- Cause (recorded before the fix): the collision loop at the end of
  `resolve_task_identity` called `_identity_derivations` for every other known
  task ID (archived ones included), and each call ran `git check-ref-format`.
  Cost was O(open tasks x known tasks): 390 ref checks, 78 per open task.
  Only the resulting names were compared, so the check was needed only for an
  ID that actually collides.
- Fix: `_identity_derivations` is now `_identity_names` (pure, no subprocess)
  plus `_check_branch_name` (the Git ref check). The collision loop compares
  pure names and runs the Git check only for a colliding ID; outcomes are
  identical (it raised only when derivation succeeded and names collided).
  The console adds `IdentityCache`, keyed by the bytes of
  `.meridian/task-identity.json`, so an identity is resolved once per task per
  process until that declaration changes; failures are not cached.
  `ConsoleState.start_refresh` runs one background worker (single flight) and
  hands results to `apply_pending` on the UI thread, so a finished snapshot
  replaces the previous one atomically and a failed one keeps the last good
  snapshot marked stale.
